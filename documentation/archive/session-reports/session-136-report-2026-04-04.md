## Step 4 — Round-Trip Diff Engine Design

A design discussion was conducted during the waiting time while Code ran the reasoner. All five design areas from the Phase 3 plan were addressed:

**Comparison scope.** The diff covers the four pipeline-generated files (`ontara-bmm.ttl`, `ontara-bmm-properties.ttl`, `ontara-bmm-weights.ttl`, `ontara-correspondence.ttl`) and their two target named graphs (`domain` and `correspondence`). OWL-authoritative content (hand-authored axioms, governance vocabulary, CQC individuals, import ontologies) is excluded per S135-D5. The scope is defined by [[concept-authority-zones|authority zones (B29)]].

**Comparison granularity.** Four semantic unit types:
1. **ClassDeclaration** — identified by IRI; properties: label, comment, definition, parent, bfoType
2. **PropertyDeclaration** — identified by IRI; properties: label, comment, domain, range, functional, subPropertyOf
3. **WeightIndividual** — identified by IRI; properties: source, target, strength, rationale, label
4. **MappingRecord** — identified by IRI; properties: sysmlElementName, owlEntity, classification, sysmlSourceFile, sysmlLineNumber, sourceHash (plus subtypes: PropertyMappingRecord, WeightMappingRecord)

**Diff categories.** Four: added, removed, modified, unchanged. Removals flagged with higher prominence (S136-D1) as potential regressions.

**Output format.** Dual: JSON file (`generated/ontara/diff-report.json`) for machine consumption and future patch automation; human-readable summary to stdout (S136-D2).

**Authority zone awareness.** The diff engine's scope is defined by what the pipeline produces, not by what GraphDB contains — a clean expression of [[concept-authority-zones|B29]] in practice. IRI namespace filters exclude `ontara-gov:` content. The engine only queries asserted content from the two named graphs, excluding inferred triples in the default graph (per S106-F2).

**Open questions resolved:**
- **S135-Q1:** Option B — generated files vs SPARQL extract. The store is the live artefact; file-to-file comparison doesn't test the right thing.
- **S135-Q2:** Already resolved by S135-D3 — standalone `diff_kg.py` with separate lifecycle from the generation pipeline.
