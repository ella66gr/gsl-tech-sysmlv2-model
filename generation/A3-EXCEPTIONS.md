# A3 exception list

Principle A3: the model generates everything. Generated files are never
edited by hand, and `make gen-check` proves it. Anything a tenant needs that
cannot be generated from the model as it stands is written by hand and
recorded here, beside the generators, so that it is visible and bound to the
part of the model it depends on.

The usual fix is to give the model what it lacks, checked by the SysML parse
check. An entry here is the fallback, not the first choice (Stage 0
specification, section 3.8 item 2).

## Format

Each entry has these fields.

| Field | What it holds |
|---|---|
| ID | `A3-NNN`, never reused |
| Tenant | The tenant whose content it is |
| What | The hand-written item, and its path relative to the tenant folder |
| Why it cannot be generated | What the model lacks, and why that is not added now |
| Model signature | The model elements the item depends on, by qualified name |
| How the binding is checked | What fails when the model signature changes |
| Added | Session and step |
| Retire when | The model change that would let it be generated |

Tenant paths are written relative to the tenant's folder under `exercises/`,
so that this file, like the generators, names no tenant folder.

## Entries

### A3-001 — Cafe audit step display labels

| Field | Value |
|---|---|
| Tenant | Cafe |
| What | `WORKFLOW_STEP_LABELS` in `packages/shared/src/workflow-constants.ts`: the display name of each fulfilment workflow step in the audit table ("Wait for Barista" and so on) |
| Why it cannot be generated | The model has no label annotation for orchestration action steps. `@UserFacing` on a usage is a known Syside parse failure (a tenant projection, S275), and adding a label attribute to the `TemporalMetadata` definitions would change the platform annotation schema, which needs Ella's decision first (section 3.8 item 3). Everything else in the step table is generated |
| Model signature | `FulfilDrinkOrchestration::FulfilDrinkWorkflow`, steps `validateOrder`, `waitBaristaStart`, `prepareDrink`, `waitDrinkReady`, `waitCollected`, `completeOrder` |
| How the binding is checked | The labels are typed `Record<FulfilDrinkStepId, string>`, where `FulfilDrinkStepId` is generated from the model's step list. Adding, removing or renaming a step fails the TypeScript build until the labels match |
| Added | S517, S0.2 |
| Retire when | The model carries a step label (for example a `label` attribute on a `TemporalMetadata` definition, if Ella approves the schema change) |

### A3-002 — Cafe axis guard and precondition tests

| Field | Value |
|---|---|
| Tenant | Cafe |
| What | `tests/axis-guard.test.mts` and `tests/axis-preconditions.test.mts`: the tests `make gen-test-guard`, `make gen-test-preconditions` and `make gen-test` run against the Cafe's generated axis guard and E6 cross-axis evaluator (Stage 0 test paths 4 and 5). They replace `tests/order-lifecycle-guard.test.mts`, retired at S0.4 with the state definition it tested |
| Why it cannot be generated | They are tests of the generated output. Generating them from the same model would test the generator against itself |
| Model signature | In the Cafe domain package: `Order::lifecycleAxis` (values placed, inPreparation, ready, collected, cancelled), `Order::paymentAxis` (unpaid, paid), `OrderLine::preparationAxis` (queued, inPreparation, ready, collected, cancelled) and its precondition `queuedToInPreparation::orderPaid` |
| How the binding is checked | The tests fail when those axes' values, moves, authorities or the precondition change, which is their purpose |
| Added | S517, S0.2; replaced S518, S0.4 |
| Retire when | Not expected to retire. They are updated when the axes change on purpose |

## Known gaps (not exceptions)

These are not hand-written exceptions in the sense above, but they are model
content that the generation path does not yet own. Each is named so that it
is not mistaken for generated or sanctioned content.

1. **Activity call defaults.** The Temporal generator uses a platform default
   for every activity call (start-to-close timeout 1 minute, 3 attempts). The
   model has no annotation for them. If a tenant needs its own values, the
   `@TemporalActivity` definition gains attributes (a platform schema change).
2. **Timer expiry behaviour.** The model declares each signal's
   `timeoutMinutes` but not what expiry means. The generated workflow logs
   the expiry and keeps waiting. Escalation or cancellation on expiry needs a
   model element first.
3. **The Cafe pathway SVG.** `generated/fulfil-drink-pathway.svg` in the Cafe
   folder (and its copy under `packages/web/static/`) was rendered from the
   Mermaid file by an external tool that is not part of this repository. It is
   not regenerated by `make gen` and not covered by `make gen-check`.
4. **The Cafe prior-art web pages.** Several pages of the existing Cafe web
   app hold hand copies of model content: the state-to-action maps and state
   labels (`packages/web/src/routes/+page.svelte`,
   `packages/web/src/routes/orders/+page.svelte`,
   `packages/web/src/routes/orders/[id]/+page.svelte`) and the 30, 15 and
   60-minute timeouts shown on `packages/web/src/routes/pathway/+page.svelte`.
   The generated next-action map (`STATE_NEXT_ACTIONS`) and step table now
   exist for them to use. They are prior art, to be rewired or retired when the
   counter surfaces are built at S0.8.
5. **The Cafe prior-art pages and callers broken by S0.4.** S0.4 removed the
   Order's `status` attribute and `OrderStatus`, the `OrderLifecycle` state
   definition, and the activities' hand-written `OrderDetails` input: the
   status axes are now the single source, and the workflow runs per order
   line with the model's `OrderLine` as its input. The following prior art
   still assumes the old shapes. It is recorded here, and never patched:
   - pages that show or branch on an order `status` or the old lifecycle
     values: `packages/web/src/routes/+page.svelte`,
     `packages/web/src/routes/orders/+page.svelte`,
     `packages/web/src/routes/orders/[id]/+page.svelte` and
     `packages/web/src/routes/pathway/+page.svelte`;
   - callers that start the workflow with the old order-shaped input
     (`customerName`, `drinkType`, `size`) and read the old state query:
     `packages/web/src/routes/api/orders/+server.ts` and the other
     `packages/web/src/routes/api/orders/` routes, and the demonstration
     client `packages/temporal/src/client/start-order.ts`, which no longer
     type-checks (it imports `orderStateQuery` and builds the old input).
   The workflow's state query is now the line's preparation value
   (`fulfilDrinkStateQuery`, generated), and the per-axis next-action maps
   are in the generated `axis-guard.ts`. These callers are replaced when the
   per-line workflow is built at S0.6 and the counter surfaces at S0.8.
